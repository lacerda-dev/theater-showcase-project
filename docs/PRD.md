# PRD — Companhia Sempre em Cena

## 1. Visão Geral do Produto

### Nome do Projeto: 

Site Institucional da Companhia Sempre em Cena

### Objetivo do Produto

Desenvolver um site institucional moderno, responsivo e de fácil navegação que apresente a Companhia Sempre em Cena, fortaleça sua presença digital, atraia novos alunos e permita que os administradores atualizem os conteúdos de forma simples, sem depender de um desenvolvedor.

### Público-alvo

- Pais e responsáveis por crianças e adolescentes
- Adolescentes interessados em ingressar na companhia
- Pessoas interessadas em conhecer o trabalho da companhia
- Administradores responsáveis pela atualização do conteúdo do site

### Problema que o produto resolve

Hoje a companhia depende principalmente das redes sociais e do WhatsApp para apresentar seu trabalho e compartilhar registros dos eventos, o que dificulta a organização das informações, reduz a credibilidade para novos interessados e limita o acesso dos alunos e responsáveis ao acervo completo de fotos e apresentações.

### Proposta de valor

O site será o principal canal institucional da Companhia Sempre em Cena, reunindo informações sobre as turmas, metodologia de ensino e um acervo organizado das apresentações realizadas em um único lugar. Além de facilitar a captação de novos alunos, permitirá que alunos e responsáveis tenham acesso organizado ao acervo completo de fotos dos eventos, enquanto os administradores poderão manter o conteúdo atualizado com facilidade.

## 2. Escopo do projeto

### O que faz parte desse projeto (MVP)

#### Funcionalidades públicas

- Site totalmente responsivo
- Página inicial apresentando a companhia
- Seção "Sobre" com informações
- Exibição de informações relevantes sobre as turmas
- Informações de contato (Whatsapp e Instagram)
- Galeria organizada por eventos
- Página individual para cada evento contendo: 
    -> capa;
    -> descrição;
    -> data da apresentação
    -> acervo de fotos

#### Funcionalidades administrativas

- Área administrativa protegida por login
- Cadastro de novos eventos
- Upload de imagens para cada evento
- Gerenciamento das informações institucionais da companhia
- Edição e exclusão de eventos

### O que deliberadamente não faz parte dele

- Área exclusiva para alunos
- Cadastro de alunos
- Sistema de permissões com diferentes tipos de acesso
- Agendamento de aulas
- Compra de ingressos
- Comentários nas fotos
- Chat interno
- Notificações
- Integração com sistema de pagamento
- Dashboard estatístico
- Aplicativo mobile
- Internacionalização 

## 3. Atores do Sistema

### Visitante

#### Objetivos

- Conhecer a companhia de teatro
- Entender como funcionam as aulas e atividades
- Avaliar a qualidade do trabalho realizado
- Visualizar eventos já produzidos
- Encontrar informações para entrar em contato
- Descobrir como se tornar aluno

#### Pode realizar

- Navegar pelas páginas públicas do site
- Ler informações institucionais sobre a companhia
- Visualizar a galeria de eventos
- Acessar a página individual de cada evento
- Ver fotos e informações dos eventos
- Consultar horários, locais e informações das turmas
- Acessar links de redes sociais
- Encontrar contato via Whatsapp

---

### Administrador

#### Objetivos

- Manter o conteúdo do site sempre atualizado
- Organizar as mídias da companhia
- Atualizar informações relevantes
- Gerenciar o conteúdo sem depender de um desenvolvedor

#### Pode realizar

- Fazer login na área administrativa
- Criar novo evento
- Editar informações do evento
- Excluir eventos
- Fazer upload de imagens
- Organizar fotos por evento
- Atualizar informações de contato
- Atualizar informações das turmas (horários, faixas etárias e locais).

## 4. Requisitos Funcionais

1. O sistema deve permitir que qualquer visitante acesse as páginas públicas do site
2. O sistema deve exibir informações institucionais da companhia
3. O sistema deve apresentar os eventos cadastrados
4. O sistema deve permitir que o visitante visualize os detalhes de um evento
5. O sistema deve exibir a galeria de imagens de cada evento
6. O sistema deve exibir as informações de contato da companhia
7. O sistema deve permitir que o visitante acesse as redes sociais da companhia
8. O sistema deve permitir que o administrador realize autenticação para acessar a área administrativa
9. O sistema deve impedir o acesso à área administrativa sem autenticação
10. O sistema deve permitir que o administrador cadastre um novo evento
11. O sistema deve permitir que o administrador edite informações de um evento
12. O sistema deve permitir que o administrador exclua um evento
13. O sistema deve permitir que o administrador faça upload de imagens para um evento
14. O sistema deve associar cada imagem ao evento correspondente
15. O sistema deve permitir que o administrador remova imagens de um evento
16. O sistema deve permitir que o administrador atualize as informações institucionais da companhia 
17. O sistema deve permitir que o administrador atualize as informações de contato exibidas no site
18. O sistema deve manter os dados cadastrados disponíveis mesmo após o encerramento da aplicação
19. O sistema deve refletir automaticamente as alterações feitas pelo administrador nas páginas públicas
20. O sistema deve exibir uma mensagem de sucesso ou erro após cada operação realizada pelo administrador

## 5. Requisitos não Funcionais

1. O sistema deve ser responsivo para todos os tipos de dispositívos
2. O sistema deve apresentar uma interface intuitiva e de fácil navegação
3. O sistema deve carregar as páginas em tempo adequado, mesmo com galerias de imagens
4. O sistema deve proteger a área administrativa por autenticação
5. O sistema deve seguir boas práticas de acessibilidade
6. O sistema deve apresentar compatibilidade com os navegadores modernos.
7. O sistema deve manter a consistência visual em todas as páginas.
